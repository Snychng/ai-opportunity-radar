# 机会生成与过滤政策

## 1. 从付费市场开始

候选的起点是“有人已经为什么付钱”，不是“AI 能做什么”。优先寻找：

- 订阅、购买、订单、收入、合同、发票
- 招聘、自由职业者、外包、咨询
- 取消订阅、退款、切换到更便宜产品
- 用户为了完成任务持续付出的时间或人工成本

对标对象使用稳定 `BENCH-XXXXXXXX`。定价页只能证明产品收费；实际收入、购买、采购、续费和招聘证据更强。

## 2. 六轴扩展

围绕每个付费对标，从六个方向扩展。每次只改变一到两个关键变量，保证点子仍可解释：

1. 细分人群：谁比大市场用户更痛、更易触达。
2. 购买触发：什么事件让用户现在就愿意买。
3. AI 新形态：代理、拍照、语音、长期记忆、主动匹配、嵌入式工作流。
4. 地区与语言：国家、语言、支付方式、文化和监管差异。
5. 渠道嵌入：WhatsApp、微信、Shopify、浏览器、表格、现有行业社区。
6. 价格与交付：订阅、按次、按结果、轻服务、模板加工具；只替代一个昂贵动作。

不要把“加一个聊天机器人”视为新形态。必须说明用户行为、交付方式或成本结构发生了什么变化。

## 3. 六项硬门槛

正式机会必须六项全部通过：

| 门槛 | 合格问题 |
|---|---|
| 已有付费市场 | 哪个产品、服务、人员或流程已经获得付款？ |
| 付款者明确 | 谁控制预算并真正付款？ |
| 当前替代明确 | 用户今天用什么产品、人力、表格或放弃来解决？ |
| 产品缺口具体 | 是价格、语言、渠道、集成、速度、复杂度还是体验缺口？ |
| 获客渠道明确 | 前 20 个用户能在哪里被直接找到？ |
| 30 天 MVP | 一人加 AI 能否只完成一个高价值动作？ |

任何一项缺失都进入拒绝池。总分、热度或想象中的市场规模不能补偿硬门槛。

## 4. A/B/R 证据层级

### A：深度候选

同时满足：

- 六项硬门槛全通过
- 目标市场存在直接购买、订阅、收入、订单、合同或发票信号
- 至少两个独立证据源
- 付款者、价格或支出、购买触发、获客渠道和 30 天 MVP 清楚

只有 A 级进入深度评分并竞争每日 Top 3–5。

### B：已验证快速点子

同时满足：

- 六项硬门槛全通过
- 有真实付费对标
- 有目标用户投诉、取消、切换、手工替代、招聘或外包证据
- 尚不足以证明为本地强付款信号，或独立来源不足以进入 A

B 级使用 `OPP`，但只写紧凑卡片，不做冗长推演。

### R：区域迁移假设

同时满足：

- 来源市场已有付费对标
- 目标地区存在具体语言、支付、渠道、价格或工作流差异
- 付款者、最小产品、迁移理由和验证路径明确
- 尚缺目标地区直接付款证据

R 级必须使用 `SIG`。输出“缺失证据”和“升级条件”，不能宣称已经验证市场需求。

## 5. 区域迁移不是简单翻译

有效区域差异至少命中一项：

- 当地主渠道不同，例如 WhatsApp、Zalo、LINE、微信
- 语言导致识别、搜索、客服或内容质量明显下降
- 本地支付、税务、身份或平台集成不同
- 国际产品价格相对当地收入过高
- 当地用户用表格、人力或外包形成稳定替代
- 行业结构、文化或法规使工作流不同

只换语言 UI 或只把国家名追加到标题，不能成为独立区域机会。

## 6. 适合本项目的产品边界

优先：

- 明确场景的 Web SaaS、App、浏览器插件、消息机器人
- 付费内容、开发者工具、嵌入式行业工具
- 有单边价值的轻平台或人工辅助撮合
- 能通过社区、插件市场、合作渠道或结果分享获客

降级或拒绝：

- “AI 帮某行业提效”这类宽泛描述
- 没有付款者或获客渠道
- 每个客户都要长期重度定制
- 无单边价值的双边平台
- 依赖非法抓取或不稳定私有数据
- 需要自建硬件、物流、支付或大规模线下网络

## 7. 不凑数规则

目标是 100–200 原始候选、20–40 B 级、30–80 R 级、3–5 A 级深度机会。任何层少于目标都允许，但报告必须说明具体缺口：付费对标不足、独立来源不足、本地付款未验证、渠道不清或 MVP 过大。

不得为了达到数量：

- 复制同一想法只换标题
- 把同一国家的同义人群拆成多条
- 把 R 级写成 B/A
- 把泛讨论当付费证据
- 对缺失字段进行无来源猜测
