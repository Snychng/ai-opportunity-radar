## 1. 用户偏好

优先寻找：

- 老需求的新产品形态
- 欧美、中国或成熟市场产品的区域化版本
- 恋爱、陪伴、成人、游戏、虚拟角色和社交娱乐
- AI 匹配、撮合和平台产品
- 有传播性、身份表达或情绪价值的消费者产品
- 可作为开源作品建立个人影响力的开发者工具

降低普通 AI 代运营、泛化提效工具、传统跨境数据分析和严重依赖平台评论抓取的机会优先级。

不要排斥红海。红海候选必须拥有明确的新能力、新人群、新地区、新渠道、新交互或新商业模式。

## 2. 三条机会轨道

### 针尖型

要求五项完整：

1. 谁
2. 在什么场景
3. 遇到什么具体问题或欲望
4. 当前如何解决
5. 第一版只替代哪个动作

“帮助电商提高效率”不合格。将任务缩到一个触发时刻和一个闭环。

### 老产品新形态

要求说明：

- 旧产品和旧行为
- 新形态
- 哪个 AI 能力变化使它现在成立
- 为什么用户会迁移
- 为什么巨头现有功能仍未覆盖

### 区域错配型

要求目标地区的直接证据。不要仅因没找到本地竞品就断言市场空白。

检查语言、文化、模板、价格、移动端、内容分发、本地渠道和常用通信工具。排除必须先解决支付、物流、银行或线下基础设施的方案。

## 3. 产品形态变换

为已验证需求尝试以下变换：

| 旧形态 | 新形态 |
|---|---|
| 搜索或目录 | 主动匹配和推荐代理 |
| 表单和配置 | 对话、语音或拍照生成 |
| 固定内容库 | 个性化实时生成体验 |
| 单人工具 | 多人协作或社交互动 |
| 固定游戏剧情 | 动态角色、关系和剧情 |
| 普通聊天 | 长记忆虚拟关系 |
| 人工中介 | AI 需求定义、筛选与匹配 |
| 专业软件 | 单任务 App、插件或机器人 |
| 内容订阅 | 个性化生成报告或体验 |
| 社区信息流 | AI 组织关系、主题和互动 |

不要把“增加聊天机器人”当成产品形态创新。解释完整用户行为为何改变。

## 4. MVP 边界

只让满足以下条件的候选进入深度机会：

- 一人加 AI 在 30 天内能完成可演示 MVP
- 核心价值主要通过 Web SaaS、App、浏览器插件、消息机器人、付费内容、开发者工具或撮合平台交付
- 允许少量人工审核、销售或撮合
- 不需要自建基础模型
- 不依赖大规模线下运营、硬件生产或基础设施建设
- 能提出 72 小时内的验证实验

初始预算不是主要限制，但时间、数据合法性和一人运营压力仍是限制。

## 5. 平台和开源机会

### 平台型

至少满足一项：

- 先提供单边工具
- 先人工完成撮合
- 从现有社区导入一侧供需
- AI 显著降低需求定义、筛选、定价或匹配成本
- 单个参与者在没有网络效应时也能获得价值

否则只放入观察池。

### 开源影响力

不要强行每天推荐。出现时说明：

- 目标开发者
- 可传播的技术亮点
- GitHub、社区或内容传播入口
- 后续托管、API、企业版或咨询路径
- 即使不商业化，对个人市场影响力的具体价值

## 6. 反例

不要推荐：

- 只有“AI 帮助某行业提效”的宽泛描述
- 必须非法抓取才能成立的数据产品
- 每个客户都需要长期重度定制的伪 SaaS
- 无单边价值的双边市场
- 只因为某帖子高热就推断存在付费需求
- 只有技术可行性，没有可触达用户和分发入口
- 只换语言 UI，没有目标地区需求证据的“本地化”
