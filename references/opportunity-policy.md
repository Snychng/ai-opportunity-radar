# 机会生成与过滤政策

最后更新：2026-09-10。

## 1. 从付费市场开始

候选的起点是“有人已经为什么付钱”，不是“AI 能做什么”。优先寻找：

- 订阅、购买、订单、收入、合同、发票
- 招聘、自由职业者、外包、咨询
- 取消订阅、退款、切换到更便宜产品
- 用户为了完成任务持续付出的时间或人工成本

对标对象使用稳定 `BENCH-XXXXXXXX`。定价页、订阅方案、发票和合同条款可以证明存在收费方案，不能单独证明已经成交。招聘与外包表明投入意图，真实付款需原文明确交易已发生；对应 `purchase` 或 `paid_*` 信号类型。

## 2. 六轴扩展

围绕每个付费对标，从六个方向扩展。脚本按输入维度组合并轮询各对标；研究者应限制变量范围，保证每个点子仍可解释。改变的候选范围必须作为假设验证：

1. 细分人群：谁比大市场用户更痛、更易触达。
2. 购买触发：什么事件让用户现在就愿意买。
3. AI 新形态：代理、拍照、语音、长期记忆、主动匹配、嵌入式工作流。
4. 地区与语言：国家、语言、支付方式、文化和监管差异。
5. 渠道嵌入：WhatsApp、微信、Shopify、浏览器、表格、现有行业社区。
6. 价格与交付：订阅、按次、按结果、轻服务、模板加工具；只替代一个昂贵动作。

不要把“加一个聊天机器人”视为新形态。必须说明用户行为、交付方式或成本结构发生了什么变化。

## 3. 六项硬门槛

正式机会必须六项全部通过：

| 门槛 | 合格问题 |
|---|---|
| 已有收费市场 | 哪个可核验对标有收费或付款信号？是否真的成交需单独说明。 |
| 付款者明确 | 谁控制预算并真正付款？ |
| 当前替代明确 | 用户今天用什么产品、人力、表格或放弃来解决？ |
| 产品缺口具体 | 是价格、语言、渠道、集成、速度、复杂度还是体验缺口？ |
| 获客渠道明确 | 前 20 个用户能在哪里被直接找到？ |
| 30 天 MVP | 一人加 AI 能否只完成一个高价值动作？ |

任何一项缺失都进入拒绝池；未知、待验证等占位值不能通过。MVP 必须含 1–30 的整数天数和具体范围。总分、热度或想象中的市场规模不能补偿硬门槛。

## 4. A/B/R 证据层级

### A：深度候选

同时满足：

- 六项硬门槛全通过
- 目标市场存在明确已付款的购买、订阅、发票、合同等信号，且同一条有效证据包含付款者、地区和支持事实
- 至少两个未撤回、非演示、有支持文本的独立原始来源；同一链接、转载或同一发布主体不能重复计数
- 扩展产生的假设通过 `candidate_verifications` 绑定当前值与候选证据；只有对标付款不能证明新细分人群也会购买
- 付款者、价格或支出、购买触发、获客渠道和 30 天 MVP 清楚

只有 A 级进入深度评分并竞争每日 Top 3–5。

### B：收费对标支持的候选

同时满足：

- 六项硬门槛全通过
- 有可核验的收费对标；如只有定价或报价，必须明确尚未确认成交
- 有目标用户投诉、取消、切换、手工替代、招聘或外包证据
- 尚不足以证明为本地强付款信号，或独立来源不足以进入 A

B 级使用 `OPP`，但只写紧凑卡片，不做冗长推演。保留 JSON 字段 `validated_ideas` 以兼容旧输入输出；这一字段只表示研究分层条件，不代表客户已验证，也不替代个人适配与真实实验。

### R：区域迁移假设

同时满足：

- 来源市场已有可核验收费对标；将报价与已付款事实分别标明
- 目标地区存在具体语言、支付、渠道、价格或工作流差异
- 付款者、最小产品、迁移理由和验证路径明确
- 尚缺目标地区直接付款证据

R 级必须使用 `SIG`。输出“缺失证据”和“升级条件”，不能宣称已经验证市场需求。

## 5. 区域迁移不是简单翻译

有效区域差异至少命中一项：

- 当地主渠道不同，例如 WhatsApp、Zalo、LINE、微信
- 语言导致识别、搜索、客服或内容质量明显下降
- 本地支付、税务、身份或平台集成不同
- 国际产品价格相对当地收入过高
- 当地用户用表格、人力或外包形成稳定替代
- 行业结构、文化或法规使工作流不同

只换语言 UI 或只把国家名追加到标题，不能成为独立区域机会。

## 6. 适合本项目的产品边界

优先：

- 明确场景的 Web SaaS、App、浏览器插件、消息机器人
- 付费内容、开发者工具、嵌入式行业工具
- 有单边价值的轻平台或人工辅助撮合
- 能通过社区、插件市场、合作渠道或结果分享获客

降级或拒绝：

- “AI 帮某行业提效”这类宽泛描述
- 没有付款者或获客渠道
- 每个客户都要长期重度定制
- 无单边价值的双边平台
- 依赖非法抓取或不稳定私有数据
- 需要自建硬件、物流、支付或大规模线下网络

## 7. 不凑数规则

默认研究容量是 100–200 原始变体、20–40 B 级、30–80 R 级、3–5 A 级深度机会。数量是上限规划与诊断提示，不是成功标准；同一需求的不同报价归入一个机会家族，保留 `variants`。任何层少于目标都允许，但报告必须说明具体缺口：付费对标不足、独立来源不足、本地付款未验证、渠道不清或 MVP 过大。

不得为了达到数量：

- 复制同一想法只换标题
- 把同一国家的同义人群拆成多条
- 把 R 级写成 B/A
- 把泛讨论当付费证据
- 对缺失字段进行无来源猜测

## 8. 付费抓取产出规则

- 先复用历史和免费来源，再形成候选与明确证据缺口。
- 付费请求必须服务于候选升级或硬门槛验证，不能只为增加原始条数。
- 每条付费证据最终必须关联到 BENCH、A/B/R 或明确拒绝理由。
- 定向搜索补证每来源每批最多 3 请求，由生成器和执行器硬性校验；两个来源合计 4 请求不违反此限制。
- 每批结束后由 Agent 评估是否新增 BENCH、合格结论或关键门槛证据；无产出时停止该来源，不追加新批。执行器能检查请求数和预算，不能自动判断商业价值。
- 报告必须公开证据利用率、单个合格结论成本和各来源关联结论数。
- overflow 仍是达到研究分层条件的结论，完整清单必须展示，不能因日报数量上限隐藏。
- 演示输入的 B/R 分层只验证流水线；不能作为真实市场成果。最终行动优先使用 [个人适配与验证](personal-validation.md) 选择一个主验证项目。
