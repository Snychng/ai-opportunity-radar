# Agent Note: 可选 Grok 与宿主协作搜索

Status: implemented

## Problem

固定来源和查询会限制机会发现。需要让 Grok 搜索 X，并让宿主及其他已有联网模型搜索网页、替代方案与反证，同时保留无 Grok 用户的正常使用路径。共享 Hermes 认证和线上服务不能因接入而被修改；搜索引用不能冒充原文或真实需求。

## Decision

- 新增独立 `search plan/collect/import/status` 文件交接层，沿用既有研究状态机。各 worker 在研究锁外搜索，唯一协调者登记回执、导入核验原文和合并观察快照。
- Grok 仅在显式启用后读取用户配置的 Hermes OAuth access token，单次调用 Responses X Search；不刷新、轮换或写回，不隐式切到 API Key。发送前落盘，结果未知不自动重发；每轮固定请求上限、并发为 1。
- 无 Grok 或认证不可用时，已配置且本轮有明确预算才生成既有 TikHub 付费入口的交接；否则交给宿主 X 搜索。TikHub 完成状态从真实执行产物派生；任何未执行任务均保留缺口。
- 候选与执行回执独立于证据。多个执行者找到同一 X 对象合并；网页导入显式同时提供原生 ID 和类型时才使用原生身份，旧输入与历史引用保持原行为。原文核验绑定当前固定修订，历史失效修订不计入当前统计。

权威步骤与配置见 [协作搜索](../../../../references/multi-model-search.md)，契约见 [数据契约](../../../../references/data-contracts.md)。

## Alternatives considered

本轮讨论过 Hermes Subscription Proxy 和 AOR 自行接管 OAuth 刷新。首版选择直接只读 access token，以便使用已实测的请求协议，避免增加常驻服务或修改共享凭据。代价是令牌失效后降级，长期无人值守的认证维护仍需单独验证。

没有直接并发复用付费执行器或研究 resume：现有预算账本与研究锁要求串行提交。也没有把模型引用直接导入为正文证据，因为 API 引用只能证明返回了链接。

## Consequences

Grok 是增强能力，无 Grok 不阻断研究；其他模型仍需要宿主真实可用的联网工具。订阅额度与现有服务共享，工具次数参数不是已验证的费用硬上限。HTTP 成功、候选数和模型一致意见不能证明商业机会成立。产品版本更新不改变既有报告与公开网站契约。

## Verification

`tests/test_grok_x.py` 覆盖 OAuth 只读诊断、引用解析、用量和失败；`tests/test_search_workflow.py` 通过真实 CLI、真实付费账本和证据导入流程验证回退、恢复、去重及原文绑定，仅替换网络边界；候选与评估各有独立测试。

2026-09-16 使用现有授权令牌完成一次新适配器阳性实测：一次 HTTP 请求、一次实际 X 搜索工具调用、两条官方机器人回复引用。该结果验证接口，不作为真实用户需求或市场覆盖验收；未执行真实 TikHub 付费请求。发行前按项目 CI 执行全量离线测试、评估与独立解包启动。
